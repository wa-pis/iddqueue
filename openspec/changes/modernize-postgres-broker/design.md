## Context

Мотивация и область изменения описаны в proposal.md. До принятия OpenSpec локальная миграция уже выполнена на базе upstream commit 80b1a490d0a494925a9f8be399a11b38cee5480a. Контракты записаны в трёх delta specs; их добавление является первой фиксацией существующего проекта в OpenSpec.

## Goals / Non-Goals

**Goals:** сохранить небольшой синхронный брокер с одной таблицей и обеспечить корректное использование Psycopg 3 в многопоточном worker; подготовить воспроизводимую поставку и GitHub CI.

**Non-Goals:** async broker, ORM, переработка модели очереди, exactly-once, новые бизнес-функции и автоматическая публикация в PyPI.

## Decisions

1. **Psycopg 3 и ленивый ConnectionPool.** Пул создаётся с open=false и открывается при первом использовании; min_size по умолчанию равен 0. Это сохраняет конструирование без I/O и не запускает потоки до обычного старта workers. Приложение должно создавать отдельный пул в каждом процессе. Открывать пул при импорте не требуется.
2. **Отдельные сессии потребителя.** LISTEN и advisory locks остаются на долгоживущих соединениях. Используются явные conn.transaction(), поскольку контекст самого соединения в Psycopg 3 закрывает его. При остановке потребителя его сессии закрываются и возвращаются в пул; подписки и locks освобождаются PostgreSQL. При кратковременном LISTEN настройки внешнего пула восстанавливаются.
3. **SQL и JSONB.** Используются Jsonb, безопасные SQL identifiers, явные casts интервалов и UUID-массив для ANY. QueryManager принадлежит конкретному брокеру/backend, чтобы настройки схемы и префикса не меняли соседние экземпляры.
4. **Результаты из таблицы.** Уведомление о результате содержит только message_id, а ожидающая сторона читает сохранённый результат. Это добавляет SELECT после уведомления и позволяет возвращать значения любого поддерживаемого таблицей размера. TTL проверяется при чтении; NOW() используется непосредственно для timestamptz. Таймаут вычисляется через monotonic с точностью миллисекунд.
5. **Поставка и CI.** Сохраняется Poetry с метаданными PEP 621 и extra binary. Удалены Psycopg 2 typings и GitLab CI. GitHub Actions содержит матрицу Python 3.10/3.13/3.14 × PostgreSQL 14/18. Удалённая матрица считается выполненной только после фактического запуска.

## Risks / Trade-offs

- Повторная доставка при падениях → сохраняется контракт at-least-once; задачи должны быть идемпотентными.
- Открытый пул не переносится через fork → ленивое создание и отдельный пул в каждом процессе; это отмечено в документации.
- Изменён формат уведомления результата → старые workers и новый backend не считаются проверенной смешанной конфигурацией; обновление выполняется согласованно.
- Локально проверена одна комбинация версий → остальные комбинации должны пройти GitHub CI до признания всей матрицы подтверждённой.
- Функциональные тесты завершают соединения → используется отдельный тестовый PostgreSQL.

## Migration Plan

1. Зафиксировать уже выполненную локальную миграцию в tasks.md и validation.md.
2. Определить владельца, имя и видимость нового GitHub-репозитория; решить, сохраняется ли временное имя пакета dramatiq-pg.
3. Создать репозиторий, настроить origin при сохранении upstream, обновить метаданные и ссылки.
4. После изменений идентичности повторить проверку сборки и импорт установленного wheel; отправить код и выполнить GitHub CI.
5. После успешной матрицы синхронизировать delta specs и архивировать change. Публикация пакета оформляется отдельно при запросе пользователя.

Локальный откат: восстановить исходный код и зависимости по upstream commit; новые проверки TTL и payload результата не требуют добавления колонок. Для существующей базы перед обновлением нужно отдельно проверить default mtime и старые TTL, записанные с преобразованием часового пояса; исправление исторических данных не заявлено выполненным.
