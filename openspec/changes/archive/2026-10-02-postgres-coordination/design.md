## Context

Dramatiq имеет стандартные лимитеры и GroupCallbacks, но наш пакет не предоставляет для них PostgreSQL backend. Общий backend позволит использовать эти функции без Redis. Текущая база — Psycopg 3 и Dramatiq 2.2.1; локальная миграция уже проверена. См. proposal.md и delta spec.

## Goals / Non-Goals

**Goals:** Лимиты и завершение групп через PostgreSQL, проверенная на реальном PostgreSQL.

**Non-Goals:** замена стандартного worker Dramatiq, exactly-once, автоматическая публикация релиза.

## Decisions

Реализовать интерфейс RateLimiterBackend Dramatiq 2.2.1; keys в incr_and_sum — callable. Хранить key/value/expires_at и состояние события в отдельной таблице координации. Проверка границ и UPSERT выполняются в транзакции под блокировкой ключа; суммирование окна защищается согласованно упорядоченными транзакционными блокировками всех затронутых ключей. LISTEN выполняется до чтения durable-состояния события; NOTIFY лишь будит ожидающих. Использовать стандартный GroupCallbacks с новым backend, не создавать второй механизм групп.

## Risks / Trade-offs

Истечение TTL занятого слота может разрешить следующую задачу, пока предыдущая ещё выполняется: требуется документировать выбор TTL. Повторная доставка может повторить вклад в стандартный барьер; exactly-once callback не заявляется. Потребуется дополнительная таблица и отдельная обратимая миграция.

## Migration Plan

Выполнить tasks.md, повторить релевантные интеграционные проверки и сборку. Для изменения SQL подготовить явную миграцию существующей базы и обратимый путь до включения новой функции. Новые опциональные возможности включаются явно. После проверки синхронизировать delta spec и архивировать change.

## Implementation Notes

Таблица содержит независимые expires_at и event_expires_at, поэтому запись события не изменяет счётчик. Имена каналов и advisory locks хешируются вместе со schema/prefix. При смене callable-окна за время ожидания locks транзакция начинается заново с упорядоченным новым набором ключей. purge удаляет только строки с истёкшими обоими TTL. Миграция generate_coordination_sql идемпотентна; init включает её, rollback требует отключить backend и удалить только его таблицу.
