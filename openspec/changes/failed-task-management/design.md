## Context

В очереди уже сохраняются rejected-сообщения, но CLI имеет только общие stats/purge/recover/flush. Для эксплуатации нужны адресная диагностика и управляемый повторный запуск. Текущая база — Psycopg 3 и Dramatiq 2.2.1; локальная миграция уже проверена. См. proposal.md и delta spec.

## Goals / Non-Goals

**Goals:** Диагностика и повторный запуск проваленных задач, проверенная на реальном PostgreSQL.

**Non-Goals:** замена стандартного worker Dramatiq, exactly-once, автоматическая публикация релиза.

## Decisions

Предлагаемые команды: failed list/show и retry MESSAGE_ID. Использовать retries metadata в message.options, а сведения последней ошибки фиксировать через небольшой middleware; хранить только нужные тип/текст/время ошибки. Для retry условный UPDATE по rejected, сброс retry-cycle options по фактическому контракту Retries и очистка устаревших result/result_ttl. Сохранять message_id, чтобы адресная диагностика оставалась связанной с исходной записью; история всех попыток в первом этапе не создаётся.

## Risks / Trade-offs

Текст ошибки может содержать чувствительные значения: вывод payload включается только явно. Возобновление требует идемпотентных actors. Middleware должен не терять исходное исключение при диагностической ошибке.

## Migration Plan

Выполнить tasks.md, повторить релевантные интеграционные проверки и сборку. Для изменения SQL подготовить явную миграцию существующей базы и обратимый путь до включения новой функции. Новые опциональные возможности включаются явно. После проверки синхронизировать delta spec и архивировать change.
