## Context

Приложение должно сохранять бизнес-данные и ставить задачу в очередь атомарно. Сейчас enqueue самостоятельно берёт соединение из пула и фиксирует отдельную транзакцию. Текущая база — Psycopg 3 и Dramatiq 2.2.1; локальная миграция уже проверена. См. proposal.md и delta spec.

## Goals / Non-Goals

**Goals:** Транзакционная отправка задач, проверенная на реальном PostgreSQL.

**Non-Goals:** замена стандартного worker Dramatiq, exactly-once, автоматическая публикация релиза.

## Decisions

Предлагаемый API: enqueue_in_transaction(message, *, connection, delay=None). Принимается синхронное соединение Psycopg 3 с активной внешней транзакцией; autocommit без внешнего transaction отклоняется. Обычный enqueue и новый путь используют общий SQL/подготовку сообщения, но только обычный путь получает retry_pg. LISTEN/NOTIFY атомарно подчиняется commit PostgreSQL. before_enqueue/after_enqueue описывают выполнение SQL, а не подтверждённый commit внешней транзакции; это явно документируется. Отдельный outbox-демон не нужен, поскольку очередь расположена в той же базе.

## Risks / Trade-offs

Задача и бизнес-данные должны находиться в одной PostgreSQL-базе. after_enqueue может выполниться до rollback приложения; hooks не должны восприниматься как гарантированный commit. At-least-once обработки сохраняется.

## Migration Plan

Выполнить tasks.md, повторить релевантные интеграционные проверки и сборку. Для изменения SQL подготовить явную миграцию существующей базы и обратимый путь до включения новой функции. Новые опциональные возможности включаются явно. После проверки синхронизировать delta spec и архивировать change.
